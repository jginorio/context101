# @context101/design — single source of truth for the design system

This package holds the **one** copy of the design system. `web/` does not
keep its own copy; it points at the files here.

## What's here

| File | What it is | Edit it? |
|---|---|---|
| `PRODUCT.md` | Strategic product/brand context for the impeccable skill | Yes — this is the real file |
| `DESIGN.md` | Visual design system (tokens, type, components, rules) | Yes — this is the real file |
| `design.json` | impeccable's machine-readable sidecar (live-panel renders from it) | Regenerated by `/impeccable document` |
| `tokens.css` | The actual CSS theme the admin imports (colors, fonts, radii, motion) | Yes — this is the real file |

## How `web/` references these (symlinks)

`web/` contains **symlinks** (pointers), not copies:

```
web/PRODUCT.md             ->  ../packages/design/PRODUCT.md
web/DESIGN.md              ->  ../packages/design/DESIGN.md
web/.impeccable/design.json -> ../../packages/design/design.json
```

A symlink is a tiny file whose entire content is a **path** to the real file. When any
tool opens it (editor, `cat`, the impeccable script, Next.js) the OS transparently
follows the pointer to the real file in this package. So:

- **Editing `web/DESIGN.md` in your editor actually edits `packages/design/DESIGN.md`** —
  there is only one file.
- The symlinks exist so the impeccable skill — which looks for `PRODUCT.md`/`DESIGN.md`
  in whatever directory you launch it from — finds the design context when you work from
  `web/`.

### Inspecting / changing the pointers

```bash
readlink web/DESIGN.md        # show where it points  -> ../packages/design/DESIGN.md
ls -la web/DESIGN.md          # the leading "l" + "->" mark it as a symlink
file -h web/DESIGN.md         # "symbolic link to ..."  (-h = don't follow it)

# repoint a symlink (overwrite in place):
ln -sf ../packages/design/DESIGN.md web/DESIGN.md

# recreate from scratch:
rm web/DESIGN.md
ln -s ../packages/design/DESIGN.md web/DESIGN.md
```

You **cannot** see the pointer by opening the file in an editor or `cat` — those follow
the link and show the target's content. The arrow is only visible via `readlink` / `ls -l`
in a terminal. That invisibility is intentional: a symlink is meant to behave exactly like
the real file for normal use.

Git stores symlinks natively (mode `120000`, blob = the target path), so `git clone`
recreates them automatically on other machines.

## impeccable context resolution

- **Launched from `web/`:** the skill finds the local `PRODUCT.md`/`DESIGN.md`
  symlink → resolves to this package.
- **Launched from the repo root:** `.claude/settings.json` sets
  `IMPECCABLE_CONTEXT_DIR=packages/design` so it resolves here too.
- `live` mode stays per-app: `web/.impeccable/live/config.json` is a **real**
  file (dev-server inject target); only `design.json` is shared.
